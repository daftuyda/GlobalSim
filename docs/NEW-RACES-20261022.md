## Rushing section boundary correction

An 18-runner, 1600 m capture exposed a float32 boundary error. At
399.9999694824219 m, `distance / (1600 / 24)` rounds to exactly 6. Comparing
distance with a multiplied 400 m threshold instead delayed rushing by one
tick. This changed which operation consumed the next shared random draw:
the expected rushing mode was 1, while the old engine selected mode 2.
The resulting movement, skills and finish times diverged, with a maximum
finish error of approximately 0.589 seconds.

The solver now compares the section quotient directly. This restores the
complete captured replay without changing the input, forcing a mode or
loosening validation. Forcing the mode alone did not restore the replay.
Two unit tests cover the rounding edge and the absence of a rushing section;
a new captured regression fixture covers the full race.

course 10804, seed 621318818, runner index 1.
